# agent-conversation-runtime Specification


## Purpose

用户可在新建的服务端数据库上启动多轮 Agent 对话，在服务重启后继续原任务，并通过现有 Web 入口查看执行进度、处理工具审批及核对最终结果。

## Requirements

### Requirement: 新库会话可持续执行
服务 SHALL 在已初始化的新库上按会话持久化增量消息，并在重启后恢复完整、有序的历史及续聊所需的执行状态。

#### Scenario: 首次启动并跨重启续聊
- **WHEN** 用户在新库完成多轮对话后重启服务，在原会话中追问先前内容
- **THEN** 客户端可读取包含此前工具结果的有序历史，Agent 能引用先前信息并继续回答，各轮消息仅出现一次

### Requirement: 工具审批绑定到原任务
服务 SHALL 在审批前暂停受控工具，按原会话的待审批操作恢复执行，并对同一审批决定的重复提交防止重复执行。

#### Scenario: 从增量检查点批准并重复提交
- **WHEN** 多轮会话暂停等待审批，服务重启后用户批准并再次提交同一决定
- **THEN** 原会话继续，受控工具仅执行一次，记录关联原工具调用和结果

#### Scenario: 拒绝受控操作
- **WHEN** 用户拒绝原会话的待审批操作
- **THEN** 受控工具未执行，用户可在该会话看到拒绝结果

### Requirement: Web 展示对话执行进度
服务 SHALL 通过现有接口提供可关联到同一任务的计划进度、流式消息、工具结果及最终状态，供两个 Web 应用在各自已有视图中展示。

#### Scenario: 用户观察多步骤对话
- **WHEN** 用户在 DataClaw Web 发起包含计划、子 Agent 和工具调用的任务
- **THEN** 用户在执行过程中可见计划更新与流式响应，子任务结果归属正确，完成时仅显示一次最终回复

#### Scenario: 管理员核对任务状态
- **WHEN** 管理员在 Agent OS Web 打开上述会话所对应的任务记录并在执行结束后刷新
- **THEN** 任务详情中的执行状态与 DataClaw Web 所见结果一致
