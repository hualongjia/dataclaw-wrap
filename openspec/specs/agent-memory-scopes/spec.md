# agent-memory-scopes Specification

## Purpose

使管理员能逐项控制 Agent 可读写的个人与共享记忆，让用户在不同应用中沿用通用称呼、保留应用专属偏好，并在明确的工作区、组织、应用或租户范围内共享约定。

## Requirements

### Requirement: 配置及解释记忆读写范围

Agent 中心 SHALL 为当前 Agent 分组显示六个独立范围开关及一个独立的自动沉淀开关，逐项常显读取者、写入者、共享边界和内容示例。

#### Scenario: 查看与修改配置

- **WHEN** 管理员打开记忆 Tab
- **THEN** 个人组展示租户内共享用户和应用内用户；共享组展示应用、工作区、组织、租户。关闭的行也可读到说明，窄屏及键盘操作均可定位各开关与关联说明。
- **WHEN** 管理员更改其中一个范围并保存、刷新
- **THEN** 当前 Agent 仅该范围改变，其他 Agent 的配置独立。

### Requirement: 升级时一次性重置已有 Agent 记忆配置

系统 SHALL 在本次升级时将所有租户已有 Agent 的六个范围开关及自动沉淀开关重置为新建默认值。重置仅涉及这七个开关。

#### Scenario: 首次升级覆盖自定义开关和缺失配置

- **WHEN** 不同租户中存在自定义过开关及缺少记忆配置的 Agent，且系统完成升级
- **THEN** 每个已有 Agent 均开启租户内共享用户、应用内用户、工作区共享记忆和自动沉淀，关闭应用共享、组织和租户记忆；其他画像字段与已存记忆内容保留。

#### Scenario: 管理员调整后的重复部署

- **WHEN** 升级成功后管理员修改某个开关，随后重启服务或重复执行该版本升级
- **THEN** 管理端和会话运行时继续使用管理员保存的值。

### Requirement: 租户内跨应用的个人记忆

服务 SHALL 按已验证租户和用户共享通用个人事实，限本人通过启用此范围的 Agent 读写。

#### Scenario: 用户称呼跨应用

- **WHEN** 用户甲在应用 A 记下「以后叫我小林」，随后在同租户应用 B 使用另一台启用该范围的 Agent
- **THEN** 甲可沿用该称呼；用户乙及同一用户标识在其他租户的会话均无法从此范围读取或覆盖甲的记录。

### Requirement: 应用内个人偏好

服务 SHALL 按租户、应用、用户隔离应用内个人记忆。同一偏好在当前应用有具体设置时，优先采用该设置。

#### Scenario: 局部覆盖

- **WHEN** 用户通用偏好是中文，在 A 指定「我在这个应用的周报用英文」
- **THEN** 该用户在 A 的后续周报采用英文，B 继续采用中文；A 的其他用户不会继承该用户的周报偏好。

### Requirement: 应用共享记忆

服务 SHALL 允许当前租户、当前应用中可使用相应 Agent 的普通用户通过会话读写应用约定，按租户和应用隔离，无需另授共享记忆写权限。

#### Scenario: 普通用户贡献应用约定

- **WHEN** 甲通过 Agent 将「本应用的红色表示待复核」写入应用共享记忆
- **THEN** 同租户应用内的乙可通过启用该范围的另一 Agent 读取并更新；不同应用或租户均不可通过该范围读取或修改。

### Requirement: 工作区、组织与租户共享

服务 SHALL 保持工作区成员、根组织以及租户各自的共享读写边界。

#### Scenario: 工作区会话

- **WHEN** 工作区所有者或成员在工作区会话中通过 Agent 写入项目约定
- **THEN** 同工作区成员可读取；个人会话、其他工作区和无访问资格的用户无法挂载该工作区记忆。

#### Scenario: 组织和租户内共享

- **WHEN** 普通用户通过启用相应范围的 Agent 写入组织约定或租户约定
- **THEN** 同根组织可跨应用读取组织约定，同租户可跨组织读取租户约定；无法确定根组织时禁用组织范围。

### Requirement: 会话与后台写入遵守同一边界

服务 SHALL 按原会话经验证的身份和有效开关确定读写目标，区分个人偏好与应用共同约定；关闭某范围或缺少必要身份时禁止向更宽范围回退。

#### Scenario: 应用身份缺失或被替换

- **WHEN** 会话无已验证应用归属，或请求自行声明另一应用 ID
- **THEN** 自报 ID 无法改变记忆目标；缺少应用归属时跳过两种应用级记忆，应用专属内容不会转存至租户内共享用户、组织或租户记忆。

#### Scenario: 直接写入与后台整理

- **WHEN** 关闭自动沉淀而保留某个范围
- **THEN** 会话仍可直接写该范围，后台不整理此轮；关闭范围本身时，直接读写和后台写入均无法使用该范围。

#### Scenario: 恢复与异步沉淀

- **WHEN** 在不同请求上下文恢复应用 A 的任务，或后台处理 A 的对话
- **THEN** 经原会话访问校验后，以原租户、应用及相应用户范围处理；后台将一般个人偏好默认记在应用内，明确通用的个人事实记在租户内个人层，仅将适用于应用全体用户的约定写入应用共享层。

### Requirement: 管理操作识别新范围

记忆管理 SHALL 在既有查看和删除权限下识别三种新范围，并按已验证租户限定列表、详情和删除目标。

#### Scenario: 核对应用记忆归属

- **WHEN** 有权限的管理员查看两个应用各自的记忆，或尝试按标识访问其他租户的记录
- **THEN** 能辨别当前租户内的范围与应用归属，访问或删除其他租户的新范围记录失败。
