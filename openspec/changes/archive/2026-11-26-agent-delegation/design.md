# 多层 Agent 委派

## Context

当前 Agent 中心按 agentType 隐藏模型和子智能体 Tab，绑定候选只接受 sub_agent。会话运行时的 createBoundSubagents 只查一层，构造普通 SubAgent。服务使用 deepagents 1.17.1，可把预先组装的可执行图作为 CompiledSubAgent 注册给上一级。

## Goals / Non-Goals

应用选择器由前置变更 application-agent-access 提供直接授权。委派复用已有 AgentSubAgentBinding，有效边表示可以调用的下级；实际委派由任务和路由提示触发。

## Decisions

1. 在租户范围维护有向无环图。沿用现有边、排序和有效状态，写入前在同一事务内按租户串行化图变更，针对提交后的整组边检查目标、环路及自绑。单靠页面过滤或事务外遍历无法防止两个管理员同时制造环。
2. 把固定类型承担的配置解开。每个 Agent 均可维护模型、运行画像、委派说明及子 Agent，管理端与 Web、桌面和初始化模板同步移除主子类型分支。入口列表继续按绑定、发布状态和入口集合筛选。
3. 从已授权入口读取可达的显式委派边，自底向上构造下级可执行图。给 B 装配 C 后，将 B 作为可执行子图注册给 A；这与只把 C 展平加入 A 的候选有不同的调用权限。多父复用只共享资产定义，每次调用独立解析当前路径、运行状态和模型。运行时检查当前路径避免损坏数据导致递归。
4. 入口沿用自身模型选择；每个下级优先解析自身默认模型，否则继承调用方实际模型。模型凭据按既有用户、租户和提供商策略校验，显式配置但不可用的模型按既有模型错误处理。工具、Skill、MCP 按实际执行 Agent 校验。上下文保留原应用、会话、入口及父调用关联，恢复时校验原入口绑定和有关委派边。

## Risks / Trade-offs

- 多层流式事件和审批可能误归属上一级 → 保留每次调用的父步骤和检查点，按原任务恢复，使用三级样例验证审批重放及最终结果。
- 共享下级在两条路径上可能继承不同模型 → 按实际调用路径解析模型，避免按 Agent ID 缓存整份已装配运行状态。

## Migration Plan

先完成应用直接访问变更，再启用新装配和统一编辑页面。保留已有委派边及画像，分阶段清理旧字段和模板。回退时停用新增多层派发并保留图数据，已启动任务按兼容的检查点版本处理。
