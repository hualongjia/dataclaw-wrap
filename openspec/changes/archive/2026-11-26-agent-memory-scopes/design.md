# Agent 记忆范围与配置页设计

## Context

AgentCenterView.vue 目前将四种记忆与沉淀开关并排展示，说明以挂载路径为主。Agent 画像、租户初始化模板、会话执行和后台任务分别归一化记忆配置。会话已有可空的 applicationId；MemoryConsolidationJob 携带租户和当轮用户但缺少业务应用 ID。现有用户快照按 userId 寻址，记忆管理服务使用命名空间正则和固定分段位置分类、过滤、删除。

## Goals / Non-Goals

首次聊天、续聊、审批恢复和后台整理均使用服务端验证的范围。开关代表当前 Agent 可以读写的数据，不向用户直接开放任意记忆路径。沿用现有存储和管理权限，桌面本地记忆文件及第三方接入协议另行规划。

## Decisions

### 身份、配置与存储

- 三个新命名空间分别按「租户、用户」「租户、应用、用户」「租户、应用」寻址。建议在 dataclaw 前缀下分别使用独立类别 tenant-users、application-users、applications，后接对应 ID 与 memory。工作区、根组织、租户沿用现有寻址及访问校验。
- 范围解析集中在服务端。应用取自已通过当前租户、应用和用户访问校验的会话；个人身份取本轮实际发言者，在共享工作区不可套用会话创建者。恢复和沉淀携带原轮身份，后台模型网关的 AppKey 不参与选择命名空间。缺少必要 ID 或上下文不匹配时禁用相应范围或拒绝访问。
- 新建与本次升级的 Agent 共用一套默认值。开启租户内共享用户记忆、应用内用户记忆、工作区共享记忆和自动沉淀，关闭应用共享记忆、组织记忆和租户记忆。管理 API、初始化模板、运行时与页面使用同一配置契约。
- 聊天挂载、文件读写许可、提示、用户快照载入及沉淀任务采用同一范围解析结果。仅装载启用且身份有效的路径。分别读取两个个人快照，优先采用当前应用中更具体的同项偏好，通用记录继续留存。关闭范围即时影响下一轮及恢复时的重新挂载。
- 对话内直接写入与后台沉淀均区分受众和内容：称呼、明确通用的偏好可进入跨应用个人层；近期业务上下文及一般偏好默认进入应用内个人层；明确适用于本应用全体的约定可进入应用共享层。目标范围不可用时跳过该项。同一应用的普通使用者可经 Agent 读写，无新增审批或角色。工作区的结构化事实确认及沉淀受管文件规则沿用。
- 管理端读删使用同一套作用域识别及租户过滤，更新列表标签、详情归属与过滤条件。新增范围以完整命名空间和 key 标识记录，防止不同应用中同名文件误删。

### Agent 中心的页面和文案

标题为「记忆配置」。说明为「选择当前 Agent 可以读取和写入的记忆范围。其他 Agent 启用相同范围后，也能在符合条件的会话中读取这些内容。」

| 分组 / 开关 | 谁能读取 | 谁能写入、适合记录什么 |
|---|---|---|
| 个人 · 租户内共享用户记忆 | 仅当前用户本人。同租户下换应用或 Agent，仍可使用这份记忆。 | 本人可通过同租户内启用此范围的 Agent 更新跨应用偏好，例如「以后叫我小林」。 |
| 个人 · 应用内用户记忆 | 仅本人在当前租户、当前应用中可用。其他用户或应用各有自己的记忆。 | 本人可通过本应用的 Agent 更新个人习惯，例如「我在这里看周报时默认看华东区」。与通用偏好冲突时，此应用优先采用本项。 |
| 共享 · 应用共享记忆 | 同租户、同应用的用户可通过启用此范围的 Agent 读取。 | 能在本应用使用该 Agent 的普通用户均可通过对话贡献或更新。例如「本应用红色表示待复核」。更新可影响同应用其他用户。 |
| 共享 · 工作区共享记忆 | 当前工作区所有者和成员可在该工作区会话中读取。 | 所有者和成员均可通过对话记录项目进展或团队约定。自动沉淀可更新工作区近期摘要与长期事实。 |
| 共享 · 组织记忆 | 当前租户内同一根组织的用户可跨应用读取。会话需能确定根组织。 | 同根组织普通用户可通过 Agent 更新组织约定，例如部门统一采用的业务术语。 |
| 共享 · 租户记忆 | 当前租户中的用户可跨组织、跨应用读取。 | 当前租户普通用户可通过 Agent 更新全租户约定，例如公司财年的起始月份。 |

两个应用范围标明「仅在会话能确定所属应用时生效」。每行常显两段说明；即使关闭开关也能了解开启后的影响。桌面左对齐范围、读取、写入、开关，窄屏按名称与开关、读取、写入纵向排列。复用 Agent 中心 Public Sans 与中文系统字体、明暗主题正文色及焦点样式。使用可聚焦的有名称控件，关联读写说明。

分组下单列「对话结束后自动沉淀记忆」。说明为「开启后，后台会将对话中值得保留的内容整理到已开启的范围。关闭后，Agent 仍可在对话过程中直接写入已开启的范围。」底部沿用「保存记忆配置」，失败保留输入，刷新和切换 Agent 后展示对应已保存值。

## Risks / Trade-offs

- **跨请求误用应用或用户。** 将原轮身份传给异步任务及恢复流程，验证异步处理前后切换应用、共享工作区内两人轮流发言的情况。
- **新路径被旧过滤条件漏掉或误分类。** 管理接口对新类别显式解析与验证，覆盖直接按 ID 查看、删除及列表的相同隔离条件。
- **个人偏好被当作公共约定。** 在对话和沉淀中提供成对例子，同时用实际持久化目标验收，不能只凭回复文本判断隔离。

## Migration Plan

在新版开放配置写入前运行有版本记录的一次性迁移。覆盖所有租户的已有 Agent，包括已自定义开关以及缺少记忆配置的 Agent。已有画像仅替换记忆配置；尚无画像的 Agent 通过统一默认值获得相同配置。重置与迁移完成记录在同一事务提交，串行执行同一版本迁移；失败可重试，已成功的迁移在重启或重复部署时跳过。管理员升级后保存的配置继续生效。空库直接使用新建默认值。

实际记忆内容独立于开关迁移。旧 userId 路径保留原数据，禁止推测租户归属或合并回旧路径。
