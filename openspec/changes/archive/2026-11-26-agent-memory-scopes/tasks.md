# 实施任务

## 1. Agent 配置契约

- [x] 1.1 同步 Agent 管理接口、初始化模板、Web 类型和运行时的七项默认值。验证新建 Agent 在管理端回显和会话运行时均采用规格中的四开三关。
- [x] 1.2 在已有画像更新路径验证只改一个开关时其他字段完整保留，保存后重新加载及切换 Agent 可分别恢复各自配置。
- [x] 1.3 实现有版本记录的一次性升级重置。以跨租户的自定义配置、空配置及缺少画像的 Agent 验证七项默认值，核对其他画像字段和记忆内容；验证失败重试可完成，成功后修改开关再重启或重复部署仍保留修改值。

## 2. 会话读取与直接写入

- [x] 2.1 用已验证租户、当轮用户和原会话应用解析新范围，保留工作区成员和根组织范围判断。验证两用户、两应用、两租户及缺失应用 ID 的命名空间和读写许可。
- [x] 2.2 更新 DeepAgent 挂载、读写工具、提示及个人快照读取。验证称呼跨应用、应用内偏好优先、普通用户可贡献应用约定，关闭范围后无法通过工具或快照取回内容。
- [x] 2.3 将同一解析用于续聊、重新生成及审批恢复。验证伪造应用 ID、共享工作区内不同发言者和恢复前关闭开关时，访问范围与新建会话一致。

## 3. 后台沉淀

- [x] 3.1 在任务入队、执行和恢复入口传递原轮身份与会话所属应用。验证请求结束或用户切换应用后，写入仍落在正确范围，缺少应用归属时跳过应用级内容。
- [x] 3.2 分别更新后台工具许可和沉淀规则，用称呼、个人报告偏好、应用公共约定检查实际写入目标。验证关闭沉淀只影响后台，工作区受管文件和结构化事实确认仍遵循原规则。

## 4. Agent 中心与记忆管理

- [x] 4.1 在记忆 Tab 实现两组六行读写说明、独立的沉淀开关和统一保存。对照设计表核对每行的读者、写入者、示例和条件，验证关闭时可读、保存失败保留选择。
- [x] 4.2 核对宽屏对齐、窄屏纵排、明暗主题和键盘焦点；在两种宽度下检查最长说明与开关标签，验证读屏名称和描述能对应正确范围。
- [x] 4.3 扩展既有记忆管理列表、详情、过滤及删除对新命名空间的识别。用不同租户及同租户两应用的同名文件核对归属、权限与删除结果。

## 5. 联合验收

- [x] 5.1 在测试库使用两个应用、两个 Agent 和普通用户，通过个人与工作区会话覆盖六类范围。对照运行时实际存储与管理端回显，验证跨用户共享、跨应用隔离、跨租户拒绝和恢复后归属。
