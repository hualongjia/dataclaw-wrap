# 多应用下的 Agent 记忆范围

## Why

现有用户记忆只按用户 ID 定位。多个应用共用会话服务后，用户希望各应用都记得自己的称呼，又希望某个应用的个人偏好和团队约定只在该应用中生效。管理员配置 Agent 时也需要知道一次写入会影响哪些用户。

## What Changes

- **BREAKING** 将原用户记忆拆为「租户内共享用户记忆」和「应用内用户记忆」，使用当前租户隔离个人信息。
- **BREAKING** 升级时将所有租户已有 Agent 的六类范围和自动沉淀开关一次性重置为新建 Agent 的默认值。重置仅涉及记忆配置。
- 增加「应用共享记忆」，同一租户、同一应用中的普通用户均可通过已启用该范围的 Agent 贡献内容。
- 保留工作区共享、组织、租户三个范围；六类开关同时控制各自的会话读写，独立的沉淀开关控制对话结束后的后台整理。
- 在 Agent 中心展示每个范围的读者、可贡献者、内容示例及生效条件，统一保存到当前 Agent。
- 覆盖会话恢复、自动沉淀和既有记忆管理读删接口对新范围的处理。

## Capabilities

### New Capabilities

- `agent-memory-scopes`：管理 Agent 可读写的六种记忆范围，在个人、应用和团队之间共享适当的信息，并按已验证身份隔离数据。

## Impact

涉及 agent-os-service 的 Agent 画像、初始化模板、会话、记忆存储与沉淀任务，以及 agent-os-web 的 Agent 配置和已有记忆管理视图。沿用现有 Postgres 记忆存储。第三方接入 API、桌面端本地记忆产品改造、Skill/MCP 授权均单独规划。
