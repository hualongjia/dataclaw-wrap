# Design

## Context

AgentOS Web 的 `DirectorySyncView.vue` 已接入全局目标和运行历史。历史接口分页返回运行记录及其逐租户结果，目标接口支持按租户 ID 新增和更新启用状态。审计日志页已有表格、分页、状态和详情弹窗样式。p3demo 提供同类操作流程及分阶段发布顺序。

## Goals / Non-Goals

页面沿用 DataClaw 主题和当前权限、审计及数据契约。调度配置由 Service 环境管理，页面显示执行记录可观测到的状态。

## Decisions

- 以同步目标、执行历史两个纵向面板组织页面。新增目标和同步全部置于目标面板工具栏。租户名与 ID 左对齐，行操作右对齐。复用审计页使用的 `TableShell`、`Table`、弹窗及现有确认交互，沿用 Public Sans、中文回退字体及现有亮暗主题变量。
- 历史行展示开始时间、触发方式、状态和结束时间。详情弹窗使用当前记录已返回的结果，保持关闭后的页码。现有历史响应包含详情数据，分页表格可以直接消费该响应。
- 分别维护目标和历史的加载、空态、错误和重试。跟踪页面发现的运行中任务以及手动提交的执行，避免浏览其他历史页时丢失进度。轮询与手动刷新需避免旧响应覆盖当前页，组件卸载时停止轮询。
- 运维文档采用 p3demo 的分阶段发布顺序，参数按 DataClaw 的实际配置记录。现有实现通过共享数据库租约协调，启用实例启动后立即尝试执行，默认周期 30 分钟。

## Risks / Trade-offs

- 历史接口随页返回逐租户结果。沿用现有分页大小，详情使用独立滚动区域，长错误文本可换行。
- 提交成功后的刷新可能失败。分别反馈提交结果和读取错误，避免操作者因为刷新报错而再次提交。
- 同步开关影响计划任务。开启时观察启动触发、同槽去重和逐租户结果，多实例使用一致的生效配置。

## Migration Plan

1. 确认 Auth3 迁移具备发布条件，执行既有目录同步数据库迁移。确认数据库、机器 Client 的目录授权和管理端权限配置。
2. 所有实例以 `DATACLAW_WEBADMIN_DIRECTORY_SYNC_ENABLED=false` 部署 Service 与 Web。
3. 用至少两个获授权的目标验证新增、启停、移除、单租户及全部执行、执行历史和失败详情，同时验证未授权目标及账号被拒绝。
4. 手动验收通过后，统一启用调度并核对 `DATACLAW_WEBADMIN_DIRECTORY_SYNC_INTERVAL_MS`，观察启动触发、同槽防重与结果。
5. 回退时先统一关闭调度，确认执行状态，再恢复已验证的兼容版本。保留目录镜像、执行历史及审计数据。
