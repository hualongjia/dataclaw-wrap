# 规格增量

## Purpose

允许同一个智能体在不同应用中作为直接入口，或在一次任务中作为其他智能体的执行者。管理员可以组合多级委派，同时保持租户、资源权限和会话边界。

## ADDED Requirements

### Requirement: 以关系表达调用角色

系统 SHALL 允许每个同租户有效 Agent 配置自己的模型及下级 Agent，并允许多个父 Agent 显式选择同一目标。管理和运行入口取消固定主子类型限制。

#### Scenario: 同一对象承担两种角色

- **WHEN** A 和 D 都绑定 B 为下级，app2 同时绑定 B 为入口
- **THEN** 管理员可以在 B 上配置模型和下级；B 可以接受 A、D 的委派，也可以从 app2 直接启动。

### Requirement: 委派图无环

系统 SHALL 拒绝自绑、跨租户目标和会形成有向环的变更，并在并发修改时维持该约束。

#### Scenario: 形成间接环

- **WHEN** 已有 A → B → C，管理员提交 C → A 或 C → C
- **THEN** 变更被拒绝，原关系保留，仍允许 D → B。

#### Scenario: 并发形成环

- **WHEN** 两个管理员同时在尚无关系的 A 和 B 上提交 A → B 和 B → A
- **THEN** 至多一条相互冲突的关系生效。

### Requirement: 通过当前委派边执行多层任务

服务 SHALL 对直接入口校验应用绑定，并逐层按实际父子委派关系和当前执行 Agent 的有效资源权限派发任务，保持原租户、应用与会话上下文。

#### Scenario: 三级委派

- **WHEN** app1 仅绑定 A，A 配置 B，B 配置 C，用户的任务触发两次委派
- **THEN** 用户可通过 A 获得 C 经 B 返回的结果，可关联到原任务及对应父子步骤；app1 的直接列表和直接调用权仍只包含 A。

#### Scenario: 边或能力被撤销

- **WHEN** 待恢复的子任务将使用已撤销的 B → C 关系或已从 C 解除的 MCP 授权
- **THEN** 恢复时停止对应派发；其他 Agent 的工具授权不能替代 C 的授权。

### Requirement: 入口与委派模型选择

服务 SHALL 让入口 Agent 使用自身模型配置，受委派 Agent 优先使用自己的有效默认模型；未配置默认模型时继承直接父 Agent 本次实际使用的模型。

#### Scenario: 跨两级解析

- **WHEN** A 使用 M1，B 的默认模型为 M2，C 未配置默认模型
- **THEN** B 使用 M2，C 也使用 M2。若 B 直接作为应用入口，则使用 B 自身的模型配置。
