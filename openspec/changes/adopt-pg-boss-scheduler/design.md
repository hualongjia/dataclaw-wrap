# 用 pg-boss 接管定时任务

## Context

ScheduledTasksScheduler 在进程启动时及每 30 秒调用 processDueTasks。ScheduledTasksService 使用内存集合防止本进程重复执行，并在同一事务中写执行记录、推进 nextRunAt。模型调用与通知在事务外发生。现有恢复逻辑还会按创建时间将超过 30 分钟的本地执行判为失败。上述判断在多个副本间缺少共同的领取和完成依据。

## Goals / Non-Goals

pg-boss 负责持久化作业、到期唤醒和多副本领取，使用服务已有 PostgreSQL 数据库和专用 schema。业务表负责租户及应用权限、任务计划、执行 ID、结果和页面展示。应用归属字段及历史回填由配套变更交付。Redis 会话、P3Demo 页面与其他后台任务各自沿用原有机制。

## Decisions

1. **每个有效计划安排下一次延时作业。** 复用现有五类计划计算方法，支持时区限定为 `Asia/Shanghai`，将 nextRunAt 作为 pg-boss 延时入队的时间。这样一次性任务和重复任务共用一个协议，避免用两套 cron 计算器解释用户计划。创建、复制、改期或恢复时在 Prisma 事务中通过同一数据库连接写入作业。暂停、删除和改期递增计划版本；旧作业即使仍在队列，也会在领取时因版本、状态或时刻不符而结束。
2. **领取与执行分阶段。** 队列载荷只携带任务标识、计划版本和预期 UTC 时刻。事务内锁定业务任务行，识别重投或过时触发，首次有效触发分配雪花执行 ID，关联持久化作业标识，推进计划并安排下一次触发。为新自动执行保存唯一的任务与计划时刻键；手动执行和旧历史可以为空。重投先查执行映射再校验当前计划，确保已推进的任务仍能恢复原执行。一次性任务不安排后继作业。
3. **同一任务串行。** 各副本通过数据库中的任务执行占用状态协调手动和自动执行；上一轮尚在运行时暂缓到期作业，保留其原计划时刻。立即运行复用原鉴权、同步详情响应及忙碌处理。用持有者版本及条件更新阻止失去租约的 worker 覆盖结果，执行完成时重新读取任务状态，防止旧执行将用户刚暂停的任务重新激活。按时续租，并以队列存活及持久化阶段判断恢复，替换对新执行一律按创建时间超时判错的逻辑。
4. **逐阶段处理重试。** 派发前提交阶段标记，使用同一执行 ID 调用 Agent；通知按执行 ID、通道和接收目标记录独立投递状态。结果与待通知记录在同一事务提交。消费前重新验证原执行凭据、应用绑定和 Agent 权限，凭据不进入队列载荷。对支持幂等或查询结果的下游使用稳定标识恢复；普通 webhook 等无法确认接收结果时，在既有详情的错误或投递说明中标明待核对，停止该阶段自动重发。业务失败策略作用于同一次业务执行，队列重试不会多次累计失败次数。
5. **锁定兼容版本。** 采用提供事务入队能力的 pg-boss 版本，在项目 Node 24、目标 PostgreSQL 版本及服务使用的 Prisma 连接上验证事务回滚。队列对象由部署迁移初始化，worker 启停纳入 Nest 生命周期；停机先停止领取，再等待在途执行或交由恢复流程。参考 [pg-boss 官方文档](https://github.com/timgit/pg-boss)。

6. **固定上海时区。** 创建、更新、复制、恢复、立即运行、导入和消费均只接受 `Asia/Shanghai`；聊天工具说明与默认值、数据库默认值保持一致。不扩展或修复其他时区的夏令时算法。切换前只读核对非上海历史任务；若存在，停止导入并等待明确的数据处置决定，绝不静默改写时区或计划时刻。五类计划验证上海跨日期和年界边界，并覆盖非上海拒绝。

## Risks / Trade-offs

- 进程可能在记录派发意图后、真正发送前退出。下游缺少幂等能力时，保守处理可能留下需核对的执行；记录阶段和执行 ID，保留后续人工判断依据。
- 历史数据可能已有重复触发。新执行使用可空唯一键，仅为可确认的新执行写入，保留原历史。多副本切换演练使用真实 PostgreSQL 和可计数的 Agent、通知替身。

## Migration Plan

1. 部署新增表结构、队列对象与可关闭的 worker。切换窗口暂缓任务写入及立即运行，停止所有旧轮询并排空或核对在途执行。旧版本无法动态停轮询时，先停止旧进程。
2. 先核对历史任务时区；存在非上海任务时暂停并获得处置决定。在消费关闭期间可重跑地按业务表的状态、版本和 nextRunAt 导入作业，并逐项核对有效任务。对逾期项从原时刻补跑，顺序推进；不重置为部署时刻。
3. 启动多个 pg-boss 消费者，恢复入口，核对首次触发、历史记录和通知。清理旧轮询入口及只适用于旧执行的恢复路径。
4. 回退时先暂停变更入口、停止新消费者并核对在途及结果未知的执行，再从业务表中已提交的 nextRunAt 恢复一个旧调度实例。保留队列记录与业务映射供对账；再次切换时丢弃失效版本并按最新业务状态校准。
