# 多实例定时调度

## Purpose

使业务用户在服务扩容、重启及升级期间仍能按原计划运行定时任务，按计划时间核对唯一的执行记录，并在外部调用结果无法确认时看到足以判断后续处理方式的状态。

## ADDED Requirements

### Requirement: 多实例触发
服务 SHALL 通过共享 PostgreSQL 协调自动触发，每个任务的每个计划时刻对应一次业务执行。

#### Scenario: 两实例同时到期
- **WHEN** 两个健康实例同时处理同一租户、同一任务、同一到期时刻
- **THEN** 历史中只有一条该时刻的自动执行，正常完成时只发起一次 Agent 调用，每个指定接收目标只收到一次对应通知

#### Scenario: 服务停机后重新启动
- **WHEN** 所有实例在下一次计划时间之前停止，随后恢复
- **THEN** 从已保存的下一计划时刻继续处理，逾期触发可被领取，同一任务按原计划逐次推进，已完成时刻不会重新派发

### Requirement: 计划操作一致性
服务 SHALL 在多实例部署中遵守用户已提交的计划状态、类型，并将支持时区限定为 `Asia/Shanghai`。

#### Scenario: 修改、暂停、恢复与删除
- **WHEN** 用户在作业领取前修改计划、暂停或删除任务，旧触发随后被消费
- **THEN** 旧触发不会派发 Agent；恢复或修改后按最新有效计划运行，删除的任务不会再次运行

#### Scenario: 计划兼容
- **WHEN** 用户创建或复制一次性、每小时、每日、每周或 cron 任务
- **THEN** 首次和后续运行使用 `Asia/Shanghai` 规则，每个副本显示相同的下一执行时间，一次性任务只自动执行一次

#### Scenario: 非上海时区拒绝
- **WHEN** 创建、更新、复制、恢复、立即运行、导入或消费涉及非 `Asia/Shanghai` 时区任务
- **THEN** 服务在 Agent 调用前拒绝；历史计划不被静默转换或改期，导入前发现此类历史任务时暂停并等待明确处置决定

#### Scenario: 手动运行
- **WHEN** 用户在两次计划之间使用立即运行
- **THEN** 接口按既有契约返回任务详情，历史标记为手动执行，下一自动执行时刻保持原值

### Requirement: 崩溃后恢复
服务 SHALL 复用原业务执行身份恢复作业，并按已持久化的派发结果决定重试范围。

#### Scenario: 派发前退出
- **WHEN** 实例在记录执行后、开始外部派发前退出
- **THEN** 可用实例接管同一次执行，页面上保留同一个执行 ID

#### Scenario: 外部结果未知
- **WHEN** Agent 或通知接收方可能已接受请求，但实例退出且响应未持久化
- **THEN** 恢复时使用同一幂等键核对或重试；下游无法确认或去重时，记录对应阶段结果待核对并停止自动重发

#### Scenario: 完成后重投
- **WHEN** 结果已持久化但队列还未确认完成，另一副本再次收到相同作业
- **THEN** 已完成的 Agent 调用与已确认送达的通知均不会再次执行

### Requirement: 执行身份
服务 SHALL 在消费时按原任务的租户、应用、凭据及 Agent 授权验证执行资格。

#### Scenario: 排队后撤销授权
- **WHEN** 任务入队后原应用凭据失效、应用归属不匹配或 Agent 已解绑
- **THEN** 执行历史可查到失败原因，服务在调用模型或工具之前停止

### Requirement: 旧计划接管
服务 SHALL 支持按既有任务的下一计划时刻接管调度，并保留历史执行。

#### Scenario: 重复运行迁移
- **WHEN** 切换期间重复导入包含到期、未来、已暂停、已完成和已删除任务的数据
- **THEN** 只有有效活动计划获得待触发作业，同一时刻只执行一次，原有历史、任务归属和暂停状态可核对
