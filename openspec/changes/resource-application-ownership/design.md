# 四类资源的业务归属

## Context

Agent、ToolRegistry、McpServerRegistry 与 SkillRegistry 分别存储资产，工具、MCP、Skill 各有独立的 Agent 授权记录。Skill 另有 ownerScope、workspaceId 和可见范围。应用身份及会话记忆范围在运行时有独立来源。

## Goals / Non-Goals

允许管理员维护业务归类，并支持从应用查找资源。维护权限继承各类资源现有管理规则，公共资源允许无归属。

## Decisions

1. 四类资产分别增加可空 ownerApplicationId（数据库 owner_application_id），与应用注册 ID 对齐，以租户和归属应用建查询索引。关联表适合多值关系；单值字段可以直接表达“至多一个”。校验目标为当前租户可选的有效应用。平台共享资源继续遵守原有编辑权限和租户边界，缺乏租户归属时保留空值。
2. 管理写入区分未提供字段、显式清空以及设置新 ID。列表和详情批量返回归属 ID 与名称，在资源允许的创建、编辑入口使用同租户应用选择器。应用删除时解除业务归属，使资源回到未指定状态，处理须保持事务一致性；单纯停用允许识别原归属。
3. 在 Agent 基本信息维护归属；绑定应用 Tab 展示应用调用关系。Agent 列表的归属筛选用 ownerApplicationId，绑定查询走应用绑定。Skill 工作空间范围与应用归属分别展示。资源授权写入、App-Key 解析和记忆范围计算均沿用各自的事实来源。

## Risks / Trade-offs

- 管理员误以为修改归属即授予访问 → 表单说明“用于标识资源的业务归属。Agent 使用资源需单独授权”，并为归属与绑定不同的案例编写验收测试。
- 编辑已有资源时旧客户端省略归属 → 部分更新保留当前值，仅显式清空时解除归属。

## Migration Plan

先做可空字段和索引的增量迁移，再发布读写 API、筛选与页面。已有记录保持未指定，避免从授权或创建者猜测历史归属。可先回退页面及读写入口并保留新增列中的数据。
