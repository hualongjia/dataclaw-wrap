# Design

## Context

运行上下文已保存原 App-Key，并能重新验证其在任务租户中的应用身份。当前 Web 和管理端共用任务服务，后台轮询也从同一张表读取到期任务。

## Goals / Non-Goals

业务端以“本人在当前应用创建的任务”为访问范围；管理端按现有查看权限提供租户全量视图。后台调度使用任务原有的执行身份。

## Decisions

- 为任务表增加可空 BIGINT 列 `application_id`，为租户、应用、创建人及软删除标志建立联合索引。复用现有 `creator` 字段识别任务创建人。
- 从可信上下文取得租户、应用和用户，对任务实际引用的空间（含知识范围中的空间）复用工作空间服务的归属及成员规则。创建、编辑、恢复和管理端复制在提交前校验，事务内锁定空间时也匹配应用和租户；有来源会话时一并核对其空间关联。立即运行与到期执行用任务原应用和创建人复核访问权，完成校验后才读取空间内容或派发 Agent。没有空间引用的任务走个人路径。
- 页面、API 与聊天工具复用任务服务及会话接入变更定义的应用范围。仅个人模式拒绝有效的空间 ID、空间来源会话及指向空间的知识范围，并核对知识范围中各会话的实际归属。缺省空间及聊天运行时的无空间占位值 `"0"` 归一为空。允许空间的应用继续校验空间归属与成员权限。
- 聊天工具 `create_scheduled_task` 保留 `sourceType = conversation` 及当前会话 ID 作为创建来源。创建和编辑时单独保存执行所需的知识范围：独立提醒保存完整指令并明确无需读取来源正文；需要会话正文的任务保存所依赖的会话 ID。归一化时避免仅凭创建来源把所有聊天任务都设为依赖正文。既有任务按其已保存的执行配置判断，后台不分析自然语言来猜测依赖。
- 删除会话时按租户、应用和被删除的会话 ID 匹配执行依赖，保留任务、来源记录及执行历史。在同一事务中暂停依赖该正文的活动任务并记录“来源会话已删除”；已暂停且仍有该依赖的任务也应能查看原因，已结束任务保留终态。派发前按当前状态和依赖复核，防止已排队的触发在删除成功后启动新执行。仅作溯源的失效 ID 不阻碍任务继续执行或编辑。对暂停任务允许修改执行配置，解除依赖后由用户显式恢复。
- 业务端创建、管理端复制时，在同一事务中写入已验证的租户、应用、登录用户和执行上下文。业务端移除模板列表和复制路由，管理端复制仍校验原应用身份。编辑、恢复及凭据更新保留原创建人和应用。新增或更换来源会话时校验其可访问且属于同一租户和应用；编辑保留的历史来源按上述溯源规则处理。
- 在 Agent OS 业务端统一构造 `tenantId + applicationId + creator + ifDelete = 0` 的查询条件，用于分页、汇总、按 ID 的读写和读取时的状态同步。执行记录通过已授权的父任务读取。管理端通过 `/api/v1/admin/scheduled-tasks` 校验 `agentos:job:view`，按当前租户查看所有创建人和应用的任务。
- DataClaw Web 直接调用 Agent OS 业务端。P3Demo 后端把下表中 `/api/v1/ai/scheduled-tasks` 下的 11 个接口映射到 `/api/v1/web/scheduled-tasks`，保留 HTTP 方法和相对路径，携带当前登录用户凭据和 P3Demo 的 App-Key。

| 操作 | HTTP 方法 | 相对路径 |
| --- | --- | --- |
| 创建 | POST | 集合根路径 |
| 分页列表 | GET | 集合根路径 |
| 详情 | GET | `:id` |
| 编辑 | PATCH | `:id` |
| 暂停 | POST | `:id/pause` |
| 恢复 | POST | `:id/resume` |
| 立即运行 | POST | `:id/run-now` |
| 删除 | DELETE | `:id` |
| 执行历史列表 | GET | `:id/executions` |
| 单次执行详情 | GET | `:id/executions/:executionId` |
| 任务统计 | GET | `:id/statistics` |

- 读取历史、单次执行或统计时，先在当前租户、应用和创建人范围内加载未删除的父任务，再按该任务限定状态同步、执行记录查询与统计。单次执行同时匹配父任务 ID 和执行 ID。历史列表保留分页与排除已定位执行的参数；P3Demo 在用户查看统计区域时请求统计。
- 后台轮询按到期时间领取候选任务，执行时核对列值与原凭据验证所得的应用 ID。一旦两者冲突即终止派发。历史空值继续走既有凭据校验，避免引入依赖 HTTP 请求身份的调度逻辑。

## 服务器投递配置

- 按用户决定，通知前端地址与路由放在 Agent OS 服务器配置 `SCHEDULED_TASK_FRONTEND_ROUTES_JSON`，以 `tenantId:applicationId` 为键，保存 `origin`、`taskPathTemplate`、`executionPathTemplate`。模板只允许同源相对路径，任务和执行 ID 由服务端替换；不使用客户端 Host 或转发头推断应用前端。P3Demo 使用 `/ai-chat?scheduledTaskId={taskId}&executionId={executionId}`，DataClaw Web 可按本身路由登记。未配置时保留结果和任务/执行 ID，不附外链。
- Webhook 新写入及实际发送仅允许 `SCHEDULED_TASK_WEBHOOK_TARGETS_JSON` 中当前租户和应用登记的完整目标 URL。历史配置仍可读取；未登记目标不能发送，发送禁止重定向，失败响应不回显外部正文或内部地址。
- P3Demo 立即运行使用独立的长操作等待时间，超时或连接中断后提示先查看历史确认，不自动重放。

## Risks / Trade-offs

- 旧记录的应用可能已删除、凭据失效或历史 ID 矛盾。只回填能在原租户验证且信息一致的记录，报告未归属数量。
- 混合版本部署期间，旧 Web 入口仍会按租户查询。所有承接相关流量的实例升级并核对回填数量后，再向 P3Demo 开放入口。

## Migration Plan

1. 增加可空列和索引，部署写入归属、校验执行身份及按应用和创建人限定访问的服务。
2. 分批处理空归属记录，按原租户验证已存凭据，并比对已有上下文应用 ID。使用仅更新空值的条件保证可重跑，覆盖滚动升级期间旧实例创建的记录。
3. 按应用、创建人核对个人列表与计数，并与管理端的租户总数及未归属记录对账，验证历史任务仍按既有规则调度。
4. 如需回退服务，先撤下 P3Demo 定时任务入口并限制旧版按租户读取的 Web 路由；保留已回填的列，便于恢复。
