# 定时任务应用归属

## Purpose

用户在 DataClaw Web 和 P3Demo 中查看、操作自己在当前应用创建的定时任务。有查看权限的用户可在 Agent OS Web 核对本租户所有用户和应用的任务及执行记录。

## ADDED Requirements

### Requirement: 新任务固定归属
系统 SHALL 从可信请求上下文取得租户、应用和登录用户，设置新建任务及管理端复制所得副本的应用归属和创建人。

#### Scenario: 创建与管理端复制
- **WHEN** 用户在应用 A 内创建任务，随后以具备权限且匹配原应用的身份通过管理端复制该任务并编辑副本
- **THEN** 两条记录分别具有独立 ID，均归属 A，创建人均为当前用户，客户端提交的归属或创建人不能覆盖服务端取值

#### Scenario: 无有效应用
- **WHEN** 业务端创建或管理端复制请求缺少可信应用身份
- **THEN** 请求被拒绝且没有新任务

### Requirement: 从个人会话创建定时任务
服务 SHALL 允许已获工具授权的 Agent 从当前用户的普通个人会话创建定时任务。聊天工具、页面及直接 API 请求遵守同一应用访问范围和创建人规则。

#### Scenario: 个人会话创建提醒
- **WHEN** 用户在没有工作空间的个人会话中向已授权的 Agent 提出计划时间明确的提醒请求
- **THEN** 工具可在未提供工作空间 ID 的情况下创建任务，默认关联当前会话，返回任务 ID；用户在当前应用的个人任务列表可查到该任务，任务的工作空间为空

#### Scenario: 来源会话归属不匹配
- **WHEN** 工具为个人任务引用属于其他租户、其他应用或其他用户的来源会话
- **THEN** 服务在写入任务前拒绝创建

#### Scenario: 工作空间会话仍可创建
- **WHEN** DataClaw Web 用户在本应用内有权访问的工作空间会话中通过已授权的 Agent 创建任务
- **THEN** 任务沿用该工作空间与来源会话的关联，并按当前租户、应用和创建人归属

### Requirement: 任务引用工作空间的边界
服务 SHALL 根据已验证应用的会话访问范围校验任务。P3Demo 首期仅支持个人任务。允许使用工作空间的应用还须校验空间属于当前租户及应用，且用户有权访问。

#### Scenario: 仅个人应用拒绝空间引用
- **WHEN** 用户经 P3Demo 页面、直接 API 或聊天工具创建任务，或编辑已有任务，显式指定工作空间 ID、引用工作空间会话或指定工作空间知识范围
- **THEN** 即使该用户是该空间的所有者或成员，服务端也拒绝写入。通过来源或知识范围中的会话 ID 间接引用空间时适用同一校验

#### Scenario: 同一用户拥有另一个应用的空间
- **WHEN** 用户从应用 A 创建或编辑任务，引用自己在同租户应用 B 拥有的空间，包括通过知识范围指定该空间
- **THEN** 服务拒绝写入；创建不会产生任务，编辑保留原配置

#### Scenario: 所有者、成员与非成员
- **WHEN** 允许使用工作空间的应用中，用户引用当前租户和应用的有效空间
- **THEN** 空间所有者和有效成员可为自己的任务关联该空间，既非所有者也非有效成员的用户被拒绝；关联成功后任务仍按创建人限定访问

#### Scenario: 跨租户或执行前权限已撤销
- **WHEN** 用户引用另一租户的空间，或任务保存后创建人失去对关联空间的访问权
- **THEN** 跨租户引用被拒绝；立即运行和到期执行均须在读取空间内容及派发 Agent 前停止处理已失去访问权的空间任务

#### Scenario: 省略空间
- **WHEN** 个人任务没有引用任何工作空间
- **THEN** 服务直接按个人任务规则校验，调用方无需选择空间或提供占位 ID

### Requirement: 删除来源会话后的任务生命周期
服务 SHALL 分别保存任务的创建来源与执行时读取正文所需的会话依赖。删除来源会话时保留任务及已有执行历史，并根据保存的执行配置决定是否暂停后续运行。

#### Scenario: 完整指令只记录创建来源
- **WHEN** 用户删除创建“每天九点提醒我开会”的会话，任务已保存完整提醒指令，执行配置无需读取该会话正文
- **THEN** 任务保留原状态和执行历史，活动任务继续按原计划运行，无需读取已删除的会话

#### Scenario: 周期任务依赖已删除的正文
- **WHEN** 用户删除“每天总结这段对话”所依赖的会话
- **THEN** 仍可运行的任务进入暂停状态，详情显示“来源会话已删除”，已有执行历史可查。依赖未解除时，手动运行、恢复和已排队的自动触发均不能发起新的执行

#### Scenario: 修改任务后显式恢复
- **WHEN** 用户编辑已暂停的任务，使保存的执行配置不再依赖已删除的正文
- **THEN** 保存后任务仍暂停；用户主动恢复且通过常规校验后，任务才按有效计划继续执行

### Requirement: 共用个人定时任务接口
P3Demo 首期 SHALL 通过自己的后端提供 11 个接口：创建、分页列表、详情、编辑、暂停、恢复、立即运行、删除、执行历史列表、单次执行详情和任务统计。全部接口与 DataClaw Web 共用 Agent OS 的租户、应用和创建人隔离规则。

#### Scenario: 两个页面调用同一业务接口
- **WHEN** 用户在任一页面创建任务、打开列表或查看一项任务
- **THEN** DataClaw Web 直接调用、P3Demo 后端按当前用户身份及本应用 App-Key 转调 `POST /api/v1/web/scheduled-tasks`、`GET /api/v1/web/scheduled-tasks` 或 `GET /api/v1/web/scheduled-tasks/:id`，详情包含任务配置、状态及最近执行结果

#### Scenario: 暂停、编辑并恢复个人任务
- **WHEN** 用户在 P3Demo 暂停本人在当前应用创建的周期任务，修改计划时间后恢复
- **THEN** 暂停后停止后续自动触发，编辑后任务仍为暂停状态；恢复成功后按最新计划和时区计算下一次运行时间

#### Scenario: 手动执行个人任务
- **WHEN** 用户在 P3Demo 对本人在当前应用创建的空闲周期任务选择立即运行
- **THEN** 服务触发一次手动执行并返回任务详情，执行记录标明手动触发，后续自动执行沿用原计划

#### Scenario: 删除个人任务
- **WHEN** 用户在 P3Demo 删除本人在当前应用创建的任务
- **THEN** 服务软删除任务及其执行记录，列表、详情和执行历史均无法再读取该任务，后续不再自动触发

#### Scenario: 查看运行结果及统计
- **WHEN** 用户在 P3Demo 查看个人任务的运行历史，或从带执行 ID 的链接进入详情
- **THEN** 用户可按时间倒序翻页或直接查看属于该任务的指定执行；页面在用户查看统计区域时单独加载该任务的运行次数、失败次数、Token 用量及预算状态

#### Scenario: 已下线的业务端接口
- **WHEN** 客户端请求 `GET /api/v1/web/scheduled-tasks/templates` 或 `POST /api/v1/web/scheduled-tasks/:id/copy`
- **THEN** 服务拒绝请求，不返回模板列表，也不产生任务副本

### Requirement: 当前应用中的个人任务
业务端 SHALL 将全部 11 个接口限定在当前租户、经 App-Key 验证的应用和当前登录用户三者的交集内。创建时写入该归属，其余接口按任务的租户、应用及创建人匹配该范围。

#### Scenario: 列表和统计
- **WHEN** 甲在同租户应用 A、B 各创建一项任务，乙也在 A 创建一项，甲从 A 查看列表、分页总数及状态统计
- **THEN** 列表、总数和统计只计入甲在 A 创建的任务；指定工作空间、搜索或状态筛选只进一步缩小此范围

#### Scenario: 按标识直接访问
- **WHEN** 用户提交同应用他人的任务 ID 或自己在其他应用的任务 ID，请求详情、统计、执行记录、编辑、暂停、恢复、立即运行或删除
- **THEN** 接口不返回目标资源，不变更目标任务，也不触发执行或通知

#### Scenario: 无应用或租户不匹配
- **WHEN** Web 请求缺少有效应用，或目标属于不同租户
- **THEN** 请求无法取得目标记录或操作该任务

#### Scenario: 执行记录与统计沿用父任务权限
- **WHEN** 用户请求同应用他人、本人其他应用或其他租户任务的执行历史、单次执行详情或统计
- **THEN** 服务在同步执行状态、读取记录或计算统计前拒绝访问，响应不包含记录、计数、用量或预算信息

#### Scenario: 执行 ID 与父任务不匹配
- **WHEN** 用户传入本人有权查看的任务 ID，却指定属于另一项任务的执行 ID
- **THEN** 接口不返回该次执行的结果或投递信息，即使用户也有权查看另一项任务

### Requirement: 管理端租户级查看
Agent OS Web 定时任务管理入口 SHALL 允许具备 `agentos:job:view` 权限的用户查看当前租户所有创建人、所有应用的任务及执行历史。

#### Scenario: 管理端查看与业务端查看
- **WHEN** 有查看权限的用户分别打开 Agent OS Web 管理列表和业务应用列表
- **THEN** 管理列表可查本租户不同用户和应用的任务，包括应用归属待确认的历史任务；业务列表仍只显示本人在当前应用创建的任务

#### Scenario: 管理端查看边界
- **WHEN** 用户缺少管理端查看权限，或有查看权限但请求其他租户任务的详情及执行记录
- **THEN** 管理接口拒绝访问目标数据

### Requirement: 历史任务兼容
系统 SHALL 仅将归属可验证的历史任务纳入相应应用的任务范围。

#### Scenario: 历史任务回填
- **WHEN** 迁移遇到可验证原应用的任务和无法验证的任务，并重复执行迁移
- **THEN** 前者归属原应用，后者保留空归属且对业务应用不可见，两者的调度时间和执行历史均保留

#### Scenario: 后台执行身份
- **WHEN** 历史任务到期
- **THEN** 调度器继续使用原任务的执行身份校验；已绑定的任务只有在经验证的运行应用与任务归属一致时才可调用 Agent

### Requirement: 可信通知目标
服务 SHALL 仅按租户与已验证应用的服务器配置生成通知外链，且新任务 Webhook 目标和实际发送都受服务器登记目标限制。

#### Scenario: 已配置的 P3Demo 执行详情链接
- **WHEN** 服务器为该租户与 P3Demo 应用配置了前端 origin 和任务、执行详情相对路由模板
- **THEN** 通知链接定位本应用指定任务及其执行；客户端请求头不能覆盖目标

#### Scenario: 未配置外链或 Webhook 目标
- **WHEN** 应用没有外链配置，或任务要求向未登记的 Webhook 地址发送
- **THEN** 没有外链时仍保留执行结果和标识；未登记的 Webhook 写入及投递被拒，历史配置可读，外部重定向与错误正文不会被传递
