# 第三方应用会话接入设计

## Context

P3Demo 的 `AiChatPage.tsx` 目前为受租户功能开关控制的占位页。业务后端的 `AgentOsClient` 已携带用户令牌和应用 App-Key 调用 Agent OS。`AiRuntimeResolverService` 仍按字符串解析入口、筛选主 Agent，模型投影缺少默认标记及凭证状态。`mapConversation` 在返回历史时丢弃了恢复计划模式需要的字段。

## Goals / Non-Goals

在原智能问答入口打通个人会话侧栏、正文、选择、发送和重开会话。沿用 `application-agent-access` 的 Agent 授权和 `agent-conversation-runtime` 的工具审批。工作空间在本期涉及服务端会话访问校验及已有应用的兼容性；P3Demo 的工作空间页面、产物抽屉、附件、知识库和数据源选择另行讨论。

## Decisions

### 上游共用会话接口，由已验证应用决定访问范围

在应用登记记录中持久化“仅个人会话”或“个人会话和工作空间会话”。鉴权中间件已有按用户租户及 App-Key 解析应用的步骤，在该步骤取得范围并传给会话服务。范围属于应用配置，不能由页面传参覆盖，也无需根据应用名称选择控制器。

两端的最近列表使用相同的个人会话查询条件及排序。按 ID 的操作在读取正文或执行动作之前校验租户、应用、会话类型、用户及具体操作权限。仅个人模式要求会话属于本人且未关联工作空间。允许空间会话时，对个人会话仍校验本人归属，对空间会话校验空间访问权及该操作的权限。工作空间下的会话列表、创建、绑定和解绑也读取同一范围。

取消生成有内存控制器和数据库状态两条路径。把访问校验放在分支之前，使当前实例持有运行控制器时也先校验归属，再中止执行。授权失败不得触发状态恢复或更新。

### P3Demo 页面与业务后端的路由

下表路径分别相对于 P3Demo 的 `/api/v1/ai/conversations` 和 Agent OS 的 `/api/v1/web/conversations`。“根路径”表示该前缀本身。

| 操作 | P3Demo | Agent OS | 接入调整 |
| --- | --- | --- | --- |
| 最近列表 | GET 根路径 | GET /recent | 复用已有调用，在上游解析、摘要映射和页面类型中透传 pinned |
| 新建、详情 | POST 根路径、GET /{id} | 同左 | 接入个人会话页面 |
| 流式发送、取消 | POST /{id}/messages/stream、POST /{id}/cancel | POST /{id}/message/stream、POST /{id}/cancel | 接入现有消息流与取消入口 |
| 重新生成 | GET /{id}/messages/{messageId}/regenerate-detail | 同左 | 取原轮信息后，在消息流请求中带 regenerateSourceUserMessageId |
| 工具审批 | POST /{id}/tool-approval/stream | 同左 | 通过审批流提交批准或拒绝并更新正文 |
| 置顶、取消置顶 | PATCH /{id}/pin | 同左 | 补 P3Demo 路由，传布尔字段 pinned |
| 改名、保存配置 | PATCH /{id} | 同左 | 补一个 P3Demo 路由，按操作传 title 或 configJson，保留未提交字段 |
| 删除 | DELETE /{id} | 同左 | 补 P3Demo 路由，服务端执行关联任务的来源删除规则，成功后移除侧栏项 |

删除会话的联动由 Agent OS 执行，避免依赖页面逐项更新任务。任务及历史保留、按保存的正文依赖暂停与解除依赖后的恢复，遵循 `bind-scheduled-tasks-to-application` 的“删除来源会话后的任务生命周期”。

### 应用后端提供页面选项

页面使用 `GET /api/v1/ai/runtime-options`。业务后端从 `GET /api/v1/agent-os/agents/list` 取有序列表，按入口数组包含 `web` 过滤，按 `agentAssetId` 调用 `GET /api/v1/agent-os/agents/{id}`。复用两条上游路由即可保留租户及应用绑定校验。App-Key 始终在业务后端。通用模型目录不能表达 Agent 对模型的绑定，无法作为此选择器的数据来源。

列表与详情的 `asset` 使用同一个数组契约，元素可为 `web`、`desktop`、`api`。保留上游排序，在可用组合中选默认 Agent。按 Agent 归集详情返回的文本、视觉和多模态聊天模型，透出 `isDefault`、`credentialMode`、`userApiKeyConfigured`。用户自行指定的有效组合用于发送；切换 Agent 时重新按新 Agent 的绑定确定默认模型。发送时复用已有的组合校验以处理加载后解绑。

供应商采用平台托管时，个人凭证状态可为空。供应商要求个人凭证且用户尚未配置时，保留该模型选项，说明原因，允许改选，并禁用普通消息和计划答案的发送。面向页面的契约只传模式和配置状态。发布状态、Agent 名称、模型名称和凭证模式属于部署数据，由运行时响应决定。

### 重开会话时按原选择续聊

从会话详情读取 `currentAgentId` 和 `currentModelId`，与当前应用的 Agent 及该 Agent 的模型绑定比对。恢复完成后再开放发送，避免默认项先加载时误用另一组合提交计划答案。

- 原组合仍可用时，选回原 Agent 与模型，包括管理员已更改默认项的情况。
- 仅原模型解绑或停用时，保留原 Agent、历史和待回答的问题，清空失效的模型选择。用户明确选好该 Agent 的可用模型后，再按所选模型的凭证状态决定是否允许发送。
- 原 Agent 已解绑时，保留有权查看的历史和计划，显示解绑原因及新建会话入口，禁用原会话发送。Agent OS 续聊时也会校验原 Agent 的绑定，因此在旧会话中切换到其他 Agent 不能恢复发送。运行选项无可用组合时，页面仍应独立加载有权查看的历史。

### 会话配置与最近一轮消息分别用于恢复

创建会话时通过 `POST /api/v1/web/conversations` 写入 `configJson.planMode`。已有会话使用业务后端转发 `PATCH /api/v1/web/conversations/{id}`，仅合并当前开关字段，避免覆盖会话其他设置。同一会话连续切换时按顺序保存，失败时展示保存失败状态。继续使用 `POST /api/v1/web/conversations/{id}/message/stream` 携带本轮 `planMode`；开启时保留 P3Demo 已有的计划提示词。

将 `GET /api/v1/web/conversations/{id}` 返回的配置布尔值、顶层 `planMode` 和有序消息映射到页面。优先取配置布尔值恢复开关，旧会话回退到顶层值。顶层值同时反映最近记录的消息模式，避免把切换开关前的一般助手回复误识别为待确认问题。本地开关缓存无法覆盖换设备或刷新后的恢复。

### 用已有消息流回答计划问题

对齐 DataClaw Web 的 `plan-question-card.ts` 可识别格式和选项语义，在智能问答页渲染已完成的助手回复。遇到普通文本保留原文。将选项和补充说明作为一条用户回答发送，刷新时用消息顺序判定问题是否仍待回答。此交互不提供服务端“确认前禁止调用工具”的保证。工具自身要求审批时，继续走独立的工具审批流程。

## Risks / Trade-offs

- **助手的问题格式可能变化。** 用 DataClaw Web 已覆盖的回复样例验证解析；无法识别的内容应允许用户以普通消息继续回答。
- **前端契约可能再次偏离上游。** 使用与真实上游一致的数组、默认项、可空凭证字段和历史会话样例验证从解析到页面的完整路径。
- **联调环境可能变更。** 2026-11-27 只读核查时，`p3demo-dev` 已发布，默认 Agent `p3demo` 绑定 `deepseek-v4-flash`，供应商为平台托管。此记录仅供选取联调样本，真实用户的模型请求仍待验证。

## Migration Plan

上线前按租户核对已有工作空间能力的应用，并为这些应用（含 DataClaw Web）回填对应范围。为 P3Demo 配置仅个人会话，新接入的第三方应用默认采用同一范围。确认存量应用配置后启用服务端校验，再上线 P3Demo 的侧栏路由、摘要字段与页面。使用两个应用各自的身份验证个人会话隔离、工作空间权限及取消行为，并在第三方接入文档记录实测结果。
