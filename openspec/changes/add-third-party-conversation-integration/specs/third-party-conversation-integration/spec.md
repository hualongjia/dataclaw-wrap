# 第三方应用会话接入

## Purpose

让第三方 Web 应用的用户在智能问答页查找和管理自己的会话，使用当前应用已获授权的 Agent 和模型，了解模型的凭证要求，并能在会话内确认计划、补充答案。服务端按应用配置和用户权限控制对个人会话及工作空间会话的访问。

## ADDED Requirements

### Requirement: 按已验证应用执行会话访问范围

Agent OS SHALL 从当前租户下已验证的应用配置读取会话访问范围。新接入的第三方应用默认“仅个人会话”，P3Demo 首期使用该范围。DataClaw Web 及已有工作空间会话能力的应用保留“个人会话和工作空间会话”范围。用户仍须满足目标会话及具体操作的权限要求。

#### Scenario: 仅个人应用直接访问会话
- **WHEN** 用户在 P3Demo 按 ID 查询详情、发消息、取消、读取重新生成详情或提交重新生成、审批工具、置顶、修改标题或配置、删除会话
- **THEN** 服务端仅接受当前租户、当前应用中属于该用户的个人会话。对于其他用户、其他应用、其他租户的会话以及工作空间会话，服务端应在读取受保护内容或执行操作前拒绝，即使用户是该空间的成员

#### Scenario: 从工作空间入口操作会话
- **WHEN** 仅支持个人会话的应用直接请求工作空间下的会话列表、创建、绑定或解绑
- **THEN** 服务端拒绝请求。客户端提交的范围参数不能扩大已验证应用的权限

#### Scenario: 保留已有应用的工作空间能力
- **WHEN** DataClaw Web 用户访问本应用下的工作空间会话
- **THEN** 有权限的空间成员可通过工作空间入口查看会话并执行获准的操作。服务端拒绝非成员访问及超出该成员操作权限的请求

#### Scenario: 取消前校验归属
- **WHEN** 调用方尝试取消无权操作的会话，包括当前服务实例持有该会话运行控制器的情形
- **THEN** 服务端拒绝取消，原生成继续运行，消息和会话状态均保持原值

### Requirement: 共用最近个人会话列表

P3Demo 的 `GET /api/v1/ai/conversations` SHALL 复用 DataClaw Web 使用的 Agent OS `GET /api/v1/web/conversations/recent`。两端均只展示当前租户、当前应用下当前用户的未删除个人会话。

#### Scenario: 用户在多个应用和工作空间中都有会话
- **WHEN** 用户打开任一应用的最近会话侧栏
- **THEN** 列表仅包含本人在该应用的个人会话，置顶项在前，各组按最近消息时间倒序排列。返回的每项摘要包含布尔型 `pinned`，刷新后可正确显示置顶状态

### Requirement: P3Demo 个人会话正文与操作

P3Demo SHALL 通过已有会话接口创建个人会话、读取有序消息、接收流式回复、取消生成、重新生成回复及处理工具审批。

#### Scenario: 新建、续聊及取消
- **WHEN** 用户新建个人会话并发送消息，在流式回复期间取消生成，再从最近列表打开该会话
- **THEN** 新会话归属当前租户、已验证应用和当前用户。回复随流更新，获准的取消停止本次生成，重开后按服务端顺序展示已保存的正文及状态

#### Scenario: 重新生成或处理工具审批
- **WHEN** 用户要求重新生成一条可重新生成的助手回复，或处理当前会话的待审批工具调用
- **THEN** 重新生成先读取该助手消息的原轮详情，再在原会话通过消息流提交源用户消息 ID。批准或拒绝工具调用通过原会话的工具审批流提交并展示结果

### Requirement: P3Demo 个人会话侧栏管理

P3Demo SHALL 允许用户置顶或取消置顶、改名和删除有权操作的个人会话，并通过业务后端复用 Agent OS 的对应接口。

#### Scenario: 置顶与取消置顶
- **WHEN** 用户切换某条个人会话的置顶状态并刷新侧栏
- **THEN** 该项的标记和分组顺序反映已保存的 `pinned` 值

#### Scenario: 改名与保存设置
- **WHEN** 用户为会话改名，随后切换计划模式，或按相反顺序操作
- **THEN** 改名与配置更新使用同一个会话 PATCH 接口。重开后标题和计划模式各自保留最后保存的值

#### Scenario: 删除个人会话
- **WHEN** 用户删除自己的个人会话
- **THEN** 操作成功后该项从最近列表移除，再次请求原会话详情也无法读取已删除的正文

#### Scenario: 从侧栏删除定时任务的来源会话
- **WHEN** 用户删除创建过两个周期任务的个人会话，一个仅记录创建来源，另一个的执行配置需要读取该会话正文
- **THEN** 两项任务及已有执行历史均可在定时任务入口查看。仅记录来源的活动任务按原计划继续，依赖正文的任务暂停，详情提示“来源会话已删除”。用户编辑解除依赖后可显式恢复该任务

### Requirement: 应用内的 Web Agent 选择

第三方智能问答页 SHALL 使用当前租户和已验证应用下已发布的绑定 Agent，按列表和详情中的入口数组识别 Web Agent，保留上游顺序并支持选择符合条件的各类 Agent。

#### Scenario: 多入口和不同 Agent 类型
- **WHEN** 当前应用绑定了入口为 `["web","api"]` 的非主 Agent、入口为 `["web"]` 的主 Agent 以及入口为 `["desktop"]` 的 Agent
- **THEN** 前两项均可展示并打开详情，第三项不出现在智能问答选择器中

#### Scenario: 初次进入
- **WHEN** 用户首次进入智能问答，应用默认 Agent 支持 Web 且有可选聊天模型
- **THEN** 页面优先选中该 Agent；默认项不可选时，按上游顺序选择第一个可用的 Web Agent

#### Scenario: 应用没有可用配置
- **WHEN** 当前应用没有满足条件的 Agent 与模型组合，包括可用 Agent 仅绑定在其他应用的情况
- **THEN** 页面提示运行配置不可用，用户无法用其他应用的 Agent 发起对话

### Requirement: 所选 Agent 的聊天模型

页面 SHALL 只提供当前 Agent 的可选聊天模型，在新会话或用户主动切换 Agent 时优先采用该 Agent 的默认模型。业务后端 SHALL 在发送时校验所选 Agent 和模型组合仍然可用。

#### Scenario: 切换 Agent
- **WHEN** 用户切换到绑定了多个聊天模型的 Agent
- **THEN** 选择器更新为该 Agent 的模型并选中其中 `isDefault: true` 的可选项；缺少可用默认项时选中首个可选模型

#### Scenario: 模型已解绑
- **WHEN** 消息提交时所选模型已从该 Agent 解绑，或该模型仅属于另一 Agent
- **THEN** 业务后端拒绝该组合，页面提示用户重新选择

### Requirement: 重开会话时恢复 Agent 与模型

页面 SHALL 根据会话记录的 Agent、模型及当前应用绑定恢复用户选择，并在原组合失效时说明可采取的操作。普通消息和计划答案适用同一发送条件。

#### Scenario: 原组合可用且默认项已变更
- **WHEN** 用户重开会话，原 Agent 与模型仍可用，而应用默认 Agent 或该 Agent 的默认模型已经变更
- **THEN** 页面选中原 Agent 和原模型，用户可用该组合续聊或回答待确认的计划

#### Scenario: 仅原模型已解绑或停用
- **WHEN** 用户重开会话，原 Agent 仍可用，原模型已解绑或停用
- **THEN** 页面保留原 Agent 及待回答的计划问题，提示重新选择模型并禁用发送。用户明确选中该 Agent 的其他可用模型且满足凭证要求后，可在原会话续聊或提交计划答案

#### Scenario: 原 Agent 已从应用解绑
- **WHEN** 有历史查看权限的用户重开会话，原 Agent 已从当前应用解绑
- **THEN** 用户仍可阅读历史消息和原计划。页面说明解绑原因，禁用原会话的消息和计划答案发送，并提供新建会话入口

### Requirement: 所选模型的凭证提示

第三方应用 SHALL 根据模型供应商的 `credentialMode` 和当前用户的 `userApiKeyConfigured` 决定是否提示配置个人凭证及是否允许发送。

#### Scenario: 用户自备凭证
- **WHEN** 所选模型的供应商为 `user_required` 且个人凭证未配置
- **THEN** 页面保留该模型选项，说明需要配置个人凭证，禁用消息和计划答案发送，允许改选其他模型。用户完成配置或改选满足凭证要求的可用模型后可以发送

#### Scenario: 平台托管
- **WHEN** 所选模型的供应商为 `platform_managed` 且用户没有个人凭证
- **THEN** 页面允许按正常流程发送，无需用户配置个人凭证

### Requirement: 会话计划模式开关

页面 SHALL 独立于模型选择维护本会话的计划模式，将当前值用于创建会话及发送消息，并在已有会话切换时立即保存开关。

#### Scenario: 创建会话和发送
- **WHEN** 用户在新会话开启计划模式后开始提问
- **THEN** 会话初始配置和该轮消息的 `planMode` 均为 true，所选 Agent 和模型保持用户选择

#### Scenario: 关闭后直接离开
- **WHEN** 最近一轮消息启用了计划模式，用户随后关闭开关，保存成功后未发消息就离开
- **THEN** 再次打开时按 `configJson.planMode: false` 显示关闭状态，即使会话详情顶层 `planMode` 为 true

#### Scenario: 恢复旧会话
- **WHEN** 会话配置缺少布尔型 `configJson.planMode`
- **THEN** 开关回退到详情顶层的布尔型 `planMode`，两者均缺失时显示关闭

### Requirement: 计划问答与恢复

计划模式下，页面 SHALL 展示助手回复中可识别的计划问题，支持选择选项和按需补充文字，将答案作为原会话的下一条用户消息发送。涉及工具调用时 SHALL 继续执行该工具已有的授权和审批规则。

#### Scenario: 确认或补充
- **WHEN** 助手给出需要确认的计划，用户选择“按计划执行”或选择需要补充说明的选项并提交文字
- **THEN** 页面通过原会话消息流提交选定答案和用户补充的文字，助手可在同一会话继续；如后续工具需要审批，仍须取得该工具审批

#### Scenario: 重开时继续回答
- **WHEN** 会话开关开启，最近一轮启用了计划模式，助手提出可识别的问题后尚无后续用户消息，且原会话的 Agent、模型和凭证满足发送条件
- **THEN** 重新打开时显示该问题及可操作的答案选项

#### Scenario: 重开已回答或关闭计划模式的会话
- **WHEN** 该问题之后已有用户消息，或用户已经关闭并保存计划模式
- **THEN** 重新打开会话时该问题不会再次要求用户回答
