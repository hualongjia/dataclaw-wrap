# Design

## Context

动机见 proposal.md。当前 Vue 页面通过 route.name 区分三种模式，角色与权限码表单内联，矩阵直接勾选并按角色保存；角色列表每页 20 条，矩阵也只展示当前页。已有 permissions 接口返回平铺 parentId，角色绑定接口返回完整绑定，人员编辑使用 RoleMemberDelta。p3demo 的 React 实现通过 RoleMatrixPanel、RoleManagementPanel、PermissionManagementPanel 和共用编辑弹窗分离职责。

本设计涉及路由兼容、编辑生命周期、矩阵完整性与并发请求，需在实现前确定状态模型。主规格中的系统管理员角色门槛与当前应用管理员实现有既有差异；本次保留当前资格接口和服务端边界，不借布局调整改变授权策略。

## Goals / Non-Goals

**Goals:** 在 Vue 中复现 p3demo 的信息层次、表格密度和弹窗工作流；统一路由同时保存旧链接语义；保留完整绑定与人员差量语义。

**Non-Goals:** 不移植 React 或引入 @ej/ui React 依赖，不更改 Auth3 API 登记、用户授权或租户同步页面。

## Decisions

### 1. 一个路由和三个明确的 Tab

使用命名路由 role-permissions，路径 `/role-permissions`；query.tab 接受 matrix、roles、permissions，缺省为 matrix，无效值规范为 matrix。旧路由显式重定向，分别指定对应 Tab。仅系统配置保留一个菜单，所有入口复用 roleManagement 守卫。相较三个菜单或路径别名，这种方式既允许刷新定位 Tab，又避免页面标题和侧栏选中状态分散。

### 2. 容器协调状态，面板和编辑器分离

RolePermissionsView 负责 Tab、当前用户/租户上下文、请求状态及编辑器；分离矩阵、角色表格、权限码层级表格和共用角色基本信息/权限/人员/权限码弹窗。复用仓库现有 Vue 样式和组件，用 scoped CSS 对齐 p3demo 搜索左置、操作右置、紧凑表格、行操作和可换行工具栏，不照搬 React 组件。

Tab 保留搜索和角色分页；仅活动 Tab 加载必要目录，共用目录保存后失效重载。用身份和租户上下文版本及请求序号拒绝迟到响应；403 或资格失效清除数据并关闭编辑器。与仅重排现有大组件相比，分离面板可避免成员选择和矩阵草稿串用。

### 3. 矩阵只展示，弹窗维护

矩阵权限为树形行、角色为列，固定表头和首列，状态点区分已绑定、未绑定、未知，角色表头提供配置权限和管理人员。矩阵自动遍历角色分页获取完整目录，检查总数和重复 ID，绑定请求维持当前最多三个并发，不把失败当空集合。每角色失败独立重试。角色管理维持独立搜索分页，不复用矩阵角色页码。

权限配置弹窗读取完整绑定基线，搜索仅过滤展示，保存提交完整 ID 集；关闭或切 Tab 统一处理 dirty。此方式取代矩阵直接勾选，避免查看时意外修改。

### 4. 使用现有权限平铺目录构造树

以 parentId 构造树，独立工具函数处理根、孤立节点、循环和重复 ID；循环/重复等非法目录显示错误并禁止相关授权保存。合法孤立节点作为根显示，避免权限消失。搜索保留祖先路径。权限码表格提供新增根权限、子权限、修改和删除；基本表单和删除确认在弹窗内，保留接口支持字段。

相较新增后端树接口，此方式复用已有完整性检查，无需扩展 API；目录不完整仍失败，不静默截断。

### 5. 统一编辑生命周期

单一编辑器状态区分基本信息、权限绑定、成员关联和权限码。关闭、Tab 切换和路由离开共用 dirty 确认，浏览器关闭用 beforeunload。保存时禁止重复提交和切换；弹窗焦点进入及恢复，Tab 支持键盘导航。成员弹窗复用 RoleMemberDelta，仅提交增删差量；保存成功重新加载列表及关联，部分失败明确说明已完成步骤，未知结果不自动重试写入。

## Risks / Trade-offs

- [完整矩阵角色较多、绑定请求增多] → 分页获取目录和有限并发，水平滚动，失败独立重试。
- [旧页面内联编辑改弹窗导致草稿丢失] → 统一 dirty 确认和保存锁，新增行为测试。
- [权限树异常导致节点丢失或无限递归] → 纯函数校验、孤立根展示与循环测试。
- [不同用户或租户复用状态] → 上下文变更立即清理，忽略旧请求，沿用服务端逐请求授权。
- [p3demo 与 Dataclaw 主题和组件不同] → 对齐布局与交互，使用 Dataclaw 主题变量，在宽屏和窄屏实测。
- [主规格与授权实现已有差异] → 记录差异，本次增量只新增页面行为，不修改资格策略条款。

## Migration Plan

仅发布管理端前端；不迁移数据库或更改 Auth3。保留旧路由重定向，更新站内链接和测试。回退时恢复前端版本；角色、权限和人员数据仍由原接口维护。发布前以已有管理员验证三个 Tab、旧链接、保存后重载和无资格直接访问限制。
