# 应用绑定与入口访问

## Context

ApplicationRegistry 保存一个 defaultAgentId。AgentsService.listAgentOsAgents 对内置应用按编码筛选，对其他应用只返回默认项；缺少 Key 的分支当前可返回租户列表。会话已保存 applicationId，但部分执行路径按 Agent ID 直接加载。应用类型还被用于按类型查找一个入口，且定时任务和两端选择器均比较单值 entryType。

## Goals / Non-Goals

建立统一的直接访问判定，供内置与第三方应用复用；本变更先于多层委派交付。管理员目录继续使用管理权限和租户范围，供管理员配置尚未绑定的资源。

## Decisions

1. 新增租户、应用、Agent 三元唯一绑定及正反向索引，主键使用雪花 ID。沿用应用的可空 defaultAgentId，避免维护两个默认标志。新增、编辑、反向解绑及删除操作共用事务，按应用串行修改绑定和默认项。失效项恢复或重试时避免重复记录；编辑页提交差量或校验读取版本，避免覆盖另一侧刚保存的更改。
2. 应用类型和 Agent 入口类型分别使用去重的受限枚举集合，以数组传输。旧 Agent 的 both 映射为 web、desktop；有效旧单值映射为单项；历史应用 lite 映射为 [web]，agentos 映射为 [api]。按请求凭据解析应用，内置入口按唯一编码定位；多选字段不再用于决定唯一应用或凭据。保留有效 App-Key，密钥前缀不参与身份判定。定时任务等原有单值调用方改为判断集合包含其入口。
3. 列表与执行共用已验证租户、应用、已发布 Agent 及有效直接绑定条件。列表先限定绑定，再按应用默认、sortNo、创建时间排序；完全相同时按 ID 保持稳定。端侧再过滤自己的入口并保留有效选择。管理端绑定搜索使用关联存在查询，先筛选后分页。
4. 个人、工作区会话、API 直接运行及异步恢复沿用原会话或任务的已验证应用与入口 Agent。在产生模型或工具副作用前重新验证。历史查看继续执行既有租户、应用、用户和工作区访问校验。缺少可信应用身份的应用入口关闭访问。
5. 两个内置应用和 Agent 都创建好后，使用初始化版本记录首次设置绑定和默认；禁止把“当前没有绑定”作为首次判定。已有明确默认项可在升级时一次性补齐对应绑定，避免由入口类型推导出整租户授权。

## Risks / Trade-offs

- 两端的聊天、任务和模型候选各有筛选逻辑 → 以同一数据集覆盖 Web、桌面和第三方列表；确保默认置顶仅影响其所属应用。
- 撤销时仍有待审批操作 → 恢复入口先重新鉴权，继续沿用审批幂等处理。

## Migration Plan

先部署关系表、数组字段和数据转换，再切换管理与运行读写。核对旧默认项、双端映射及初始化重跑后再清理旧字段。回退窗口保留可恢复的旧值；已产生多选配置时，以备份恢复或前向修复避免有损降级。
